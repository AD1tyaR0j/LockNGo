# Physical-access threat model (Milestone 1)

| Threat                              | Mitigation now                                                                                                                                 | Gap / next step                                                 |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Stolen customer phone               | Session revocable; unlock needs an authenticated request inside the booking window                                                             | Biometric app lock; session management UI                       |
| PIN guessing                        | 6-digit CSPRNG PIN, HMAC-peppered hash, credential locked after 5 failures, device-level rate limit                                            | Kiosk lockout UX; alerting on repeated failures                 |
| PIN interception                    | Shown once; reissue revokes the old one                                                                                                        | SMS delivery needs provider review                              |
| Replayed unlock command             | Unique command id + nonce, 60 s TTL, single in-flight command per compartment, ack must match nonce                                            | Signed envelopes verified on the controller (Phase 2)           |
| Courier/staff browsing compartments | No manual-unlock UI; access is tied to one booking + compartment                                                                               | Courier scoped credentials (Phase 3)                            |
| Compromised controller              | Per-device token, hash-only storage; a device can only see/ack its own commands and report on its own compartments                             | mTLS certs, revocation, firmware attestation                    |
| Door forced open                    | Door open without an authorised command → NEEDS_INSPECTION + audit alert                                                                       | Real-time alerting/notifications                                |
| Sensor failure / door left open     | Timeout fails the command, flags the compartment, booking not advanced                                                                         | Maintenance ticket automation                                   |
| Power/network loss                  | Unlock refused while device offline; heartbeat timeout marks OFFLINE                                                                           | Offline-access policy (open decision)                           |
| Insider misuse                      | Granular permissions; support is read-only; staff booking views and every sensitive change are audited; audit tables are append-only (trigger) | Production DB role with INSERT/SELECT only on audit tables; MFA |
| Wrong compartment assignment        | Allocation and unlock are server-side; device events validated against the device's own bank                                                   | Physical labelling checks at install                            |
| Disputes over missing items         | Full booking event timeline with actor types                                                                                                   | Evidence photos, weight sensors, insurance policy               |
